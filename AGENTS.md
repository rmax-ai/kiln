# AGENTS.md — Kiln

> Working conventions for coding agents (Codex and others) in this repo.
> The spec is SPEC.md; architecture is docs/architecture.md. These are normative — do not deviate.

## Project DNA

Kiln is a **knowledge compiler and curator**. Sources → catalog → curation → canonical KB → deterministic graph compiler → static site. The LLM is never the source of truth; agents propose, humans decide. Every durable record carries provenance.

## Non-negotiables (do not "simplify" these away)

1. `knowledge/**` mutates ONLY through `applyChangeSet()` or explicit curation commands. No direct writes from pipeline code, agents, or tests except through those paths.
2. `generated/**` is disposable. Never hand-edit. Never commit. Always regenerated by the compiler.
3. `packages/domain` imports nothing from sibling packages. Anyone may import it.
4. Every durable record has `schemaVersion`, `id`, `createdAt`, `updatedAt` (except immutable-once types which have only `createdAt`).
5. Every assertion has `evidence` + `provenance`. No provenance-less assertions, even in tests.
6. Deterministic logic before LLM calls: ID validation, schema validation, alias matching, normalization, reference resolution, duplicate detection are plain code — never model calls.
7. Zod schemas for every record type, explicitly versioned.
8. Agents never write canonical files; they write proposals. Test this.
9. One durable record = one JSON file. JSONL only for scanned collections (catalog, telemetry).
10. Filesystem path derives from ID, never the reverse.

## Conventions

- **TypeScript strict**, Node 22, pnpm workspace, Vitest, Biome. `pnpm lint`, `pnpm typecheck`, `pnpm test` must pass before every commit.
- **Zod v4** (`zod@^4`). Use `.safeExtend()` for refined schemas. Watch schema ordering — Zod v4 evaluates refinements in declaration order.
- **IDs**: `{kind}:{slug}` per docs/architecture.md §4. Never invent a new kind without a decision.
- **Determinism**: same inputs + same accepted knowledge = same compiled output. No timestamps, no Math.random(), no iteration-order dependence inside the compiler or ID derivation. ULIDs only for event records (decisions/proposals/changesets).
- **Errors**: structured error types with exit codes at the CLI boundary; no console.log in library code (use the logger in `packages/telemetry` — stub until Phase 8, then real).
- **Naming**: files kebab-case; test files `*.test.ts` next to source or in `tests/` for cross-package.
- **No `.env` files.** Secrets via env vars only (see direnv-project-secrets skill). No API keys in fixtures or tests.
- **TDD for new behavior**: failing test → implement → green → commit. Golden-file tests for parser, compiler, ChangeSet.

## Verification gates (per commit)

```bash
pnpm lint && pnpm typecheck && pnpm test
```

`pnpm kb validate` additionally runs the reference checker over the full corpus. CI mirrors this exactly.
